# 简单版工作空间

更新：2026-11-14。

## 使用方式

控制台只围绕活动、券库、短链和流量开展工作。新账号默认建立个人工作空间，不需要填写商家名称、创建店铺或维护成员。由公开活动进入注册时建立领券用户账号。

- 一场活动选择一张优惠券，保存投放数量、每人限领和预算。
- 活动主链指向本场领券页，渠道入口以 `?c=渠道标识` 区分来源，使用同一份活动库存。
- 普通短链独立使用，指向外部网址。
- 访问、预约、领取、核销和退款次数继续按活动与入口归因；流量预测、限流和预热保留。
- 活动类型已接入轻量资格校验：`优惠券推广活动` 不限资格；`新客领取活动` 要求用户在该工作空间尚未领取过优惠券；`会员专享活动` 要求用户在该工作空间至少有一次历史核销记录。

## 数据兼容

这次是业务依赖简化，没有强删历史表：

- `iam_user` 直接通过 `iam_merchant.owner_user_id` 拥有一个工作空间。既有 `merchant_id` 列名继续充当数据归属标识，防止改表名和搬迁历史数据造成中断。
- 新 WORKSPACE 注册不创建 `iam_merchant_member`、`iam_shop` 记录。旧 MERCHANT、USER 注册接口和原成员关系保留兼容。
- `offer_plan.store_code` 和 `campaign_offer.store_code` 可为空。券创建无需店铺；旧接口主动传店铺编号时，仍核对归属。
- 活动与券之间的 `campaign_offer` 和 `offer_inventory` 继续处理库存投放、回收及限领。没有把并发库存和流水压进单张活动表。
- 店铺、成员、批量发券从前端路由和菜单移除，原后端接口保留。

## 表单与界面

活动创建、详情、修改、复制均保存 `activityType` 和 `budgetAmount`，不选券的草稿也保存预算。编辑预算时校验已投放券的最大让利。旧客户端省略新增字段时保留原值。

清理主要页面副标题、重复规则说明、技术解释、公式教学和小贴士。保留业务数据、必要状态、错误原因、模拟预览标记和停用/终止确认。

## 升级

已有数据库先备份，再按顺序执行一次 `V008__simple_workspace_activity.sql`。空库按 V001 到 V008 初始化；compose 已补齐全部脚本挂载。不要重复运行 V008。

真实容量报告、消息吞吐监控与历史到场率自动校准不在本次完成范围；现有页面继续展示实际未验证状态。
